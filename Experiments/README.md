# Week 6 – Model Evaluation and Experimentation

## Overview

This folder contains the Week 6 experiments for the **Smart Surveillance Entry/Exit Counter** project.

The purpose of this task was to evaluate the existing Week 5 surveillance system and investigate how different YOLO model configurations affect counting accuracy and processing speed.

The same surveillance video was used for all experiments to ensure a fair comparison.

## Objectives

- Establish a baseline using the existing YOLOv8n model.
- Measure automatic entry and exit counts.
- Calculate counting error against manually verified counts.
- Measure video processing speed (FPS).
- Experiment with different model configurations.
- Compare results and identify the most suitable configuration.

## Experimental Setup

| Parameter | Value |
|---|---|
| Input video | Same surveillance video used in Week 5 |
| Frames processed | 360 |
| Baseline model | YOLOv8n (`yolov8n.pt`) |
| Tracking algorithm | ByteTrack |
| Manual entry count | 3 |
| Manual exit count | 5 |
| Total manual crossings | 8 |

## Experiments

Four configurations were tested:

1. **Baseline:** Original YOLOv8n configuration.
2. **Confidence 0.4:** Increased the detection confidence threshold to 0.4.
3. **Image Size 960:** Increased the inference image size to 960.
4. **YOLO11s Model:** Replaced YOLOv8n with YOLO11s.

Only one configuration setting was changed at a time compared with the baseline.

## Results

| Experiment | Model | Confidence | Image Size | Automatic Entries | Automatic Exits | Count Error | FPS |
|---|---|---|---|---:|---:|---:|---:|
| Baseline | YOLOv8n | Default | Default | 2 | 1 | 62.5% | 4.36 |
| Confidence 0.4 | YOLOv8n | 0.4 | Default | 3 | 1 | 50.0% | 4.76 |
| Image Size 960 | YOLOv8n | Default | 960 | 3 | 2 | **37.5%** | 2.43 |
| YOLO11s Model | YOLO11s | Default | Default | 2 | 1 | 62.5% | 1.58 |

## Count Error Calculation

The count error was calculated using the following formula:

`Count Error (%) = (|Automatic Count - Manual Count| / Manual Count) × 100`

The total manual count was 8 crossings (3 entries + 5 exits).

For example, the baseline detected 3 total crossings:

`(|3 - 8| / 8) × 100 = 62.5%`

## Key Observations

- **Baseline:** Provided 4.36 FPS with a count error of 62.5%.
- **Confidence 0.4:** Improved the count error to 50% and achieved the highest processing speed of 4.76 FPS.
- **Image Size 960:** Achieved the lowest count error of 37.5%, but processing speed decreased to 2.43 FPS.
- **YOLO11s:** Did not improve counting accuracy and achieved 1.58 FPS, the lowest speed among the tested configurations.

## Conclusion

Among the tested configurations, Image Size 960 achieved the best counting accuracy, reducing the count error from 62.5% to 37.5%.

Confidence 0.4 provided a better balance between counting accuracy and processing speed, achieving 50% count error at 4.76 FPS.

The results demonstrate that increasing image size can improve detection and counting performance, but it also increases processing time. A suitable configuration should therefore balance accuracy and speed according to the system's requirements.

## Limitations

- Testing was performed on one surveillance video containing 360 frames.
- The system undercounted exits in all four experiments.
- Missed detections, tracking ID switches, people crossing together, and virtual line placement may affect counting accuracy.
- Processing FPS depends on the hardware and execution environment.

Further experiments with tracker settings, detection thresholds, and virtual line placement may help improve the system.
